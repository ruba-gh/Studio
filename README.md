# شركاء ستوديو ربى

بوابة عربية لإحالات المسوّقين ومتابعة العمولات والصرف. الواجهة تُنشر من فرع `main` على GitHub Pages.

[فتح لوحة الشركاء](https://ruba-gh.github.io/Studio/)

## ملفات المشروع

- `index.html` و`assets/studio.css` و`assets/studio.js` تحتوي واجهة HTML وCSS وJavaScript.
- `assets/connection.js` يتصل بواجهة التطبيق الحالية. جلسة GitHub Pages محفوظة في ذاكرة التبويب، وإعادة تحميل الصفحة تتطلب تسجيل الدخول من جديد.
- `supabase/functions/studio/` يحتوي طلبات الدخول والإحالات والصرف. يعتمد على جلسات التطبيق، ويتأكد الخادم من صلاحية الحساب لكل عملية.
- `supabase/schema.sql` يعرّف جداول PostgreSQL في مخطط خاص. ما فيه مفاتيح اتصال أو بيانات حسابات في المستودع.
- الملفات الموجودة في `app/` و`worker/` تخدم رابط الموقع السابق وواجهة البيانات اللي تستخدمها النسخة الحالية.

## تجهيز Supabase

وظائف Supabase وجداولها جاهزة واختُبرت ببيانات تجريبية. النسخة المنشورة تستخدم القاعدة الحالية إلى حين الموافقة على نقل الحسابات والإحالات.

### تشغيل نسخة مستقلة

1. طبّق `supabase/schema.sql` على مشروع Supabase مستقل وفارغ.
2. انشر `supabase/functions/studio`. الدالة تستخدم عنوان PostgreSQL المقدم وقت التشغيل من Supabase. تبقي إعداد `verify_jwt` معطلًا لأن الدالة تتحقق من جلسات التطبيق.
3. غيّر رابط الدالة في `assets/connection.js` وقاعدة `connect-src` في `index.html`. لو تغيّر نطاق GitHub Pages، حدّث `dashboardOrigin` في الدالة.
4. مع قاعدة فارغة، اضبط `STUDIO_SETUP_KEY` كسر للدالة واستخدم شاشة تهيئة الإدارة في الموقع الأساسي مرة واحدة. اسم دخول الإدارة هو `admin`.

## طريقة الاستخدام

- تضيف الإدارة كل حساب بكود وكلمة مرور ونسبة عمولة. يستخدم المسوّق الكود كاسم دخول، ويقدر يغيّر كلمة مروره من الإعدادات.
- يفتح رابط الإحالة واتساب برسالة فيها كود المسوّق. بعد استلام الرسالة، تسجل الإدارة الطلب وتتابع المبلغ المستلم.
- تُحتسب العمولة على الدفعات المستلمة. تُراجع الأرصدة كل ١٤ يومًا بتوقيت الرياض، ويُرحّل الرصيد الأقل من ١٠٠ ريال.
- تُنفّذ الحوالة خارج الموقع. تسجل الإدارة مرجع الحوالة بعد تنفيذها، وتظهر في سجل المسوّق.
